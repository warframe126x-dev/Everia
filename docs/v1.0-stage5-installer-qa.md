# Stage 5 Windows installer QA

The unsigned 1.0.0 candidate uses electron-builder 26.17.0's assisted NSIS
installer. The default choice is per-user; the standard installation-mode page
also offers an all-users choice, which may require elevation. Select a writable
location for the chosen scope. The directory page allows a custom application
location. The ordinary Start Menu and Desktop shortcuts are enabled; the
assisted wizard's Desktop shortcut choice should be verified on a real PC.
No custom NSIS script, updater, or profile relocation is included.

Everia continues to use the same per-user `%APPDATA%\Everia` profile from the
portable build. Uninstall removes application files and installer registration,
but leaves the library, IndexedDB artwork, protected credentials, window state,
backup configuration, and `.everiabackup` files alone. The portable ZIP remains
the unpacked `Everia-win32-x64` application folder.

## Chris's real-PC checklist

1. Create a verified `.everiabackup` on another drive before installer testing;
   retain the populated profile and original portable copy.
2. Install for the current user to a selected writable directory. Check the
   Start Menu shortcut, the offered Desktop shortcut choice, Installed Apps
   entry, 1.0.0 metadata, and a clean installed launch.
3. Verify the existing library, local covers/wallpaper, EN/FR/AR locale,
   Interface Scale, Settings, backup destination, window state, and saved
   provider configuration under the same Windows account.
4. Rerun the installer and check that the library persists. Test a different
   writable install location and verify shortcut targets.
5. Uninstall, confirm application files and shortcuts are removed, and confirm
   `%APPDATA%\Everia` and any selected backup destination remain intact.
6. Reinstall and verify the original library and artwork return without manual
   restore. Launch the portable ZIP under the same user and confirm it sees the
   same profile.

Unsigned QA binaries will show an unknown publisher and may prompt Windows
SmartScreen. Signing is a separate release decision. The dirty-Settings
window-close limitation remains deferred from Stage 4.
